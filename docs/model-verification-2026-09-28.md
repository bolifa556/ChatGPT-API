# 兼容通道改动与完整功能验证记录

日期：2026-09-28，北京时间。适用于本机 OpenAI.Codex 26.924.2738.0、原生 app-server 0.158.0-alpha.2.1，以及当前 14 个网关模型。测试结论针对本次构建和已列出的场景，不把受控测试当作所有远程业务功能已实测。

## 要求与已实现的改动

以原生客户端为准：客户端负责工具执行、历史、压缩、权限和对话管理，兼容层只转换必要的消息字段。未修改原生客户端，未增加网络重试，未增加任务提示词、生成摘要、重写保存的历史或创建替代聊天库。测试对话、文件和 MCP 服务位于隔离测试目录，不是用户的真实聊天记录。

1. **修复官方工具继承。** 官方 `input.additional_tools` 留在原位，后续增量请求继续继承；只有面向无状态网关的完整请求才提取顶层工具目录。旧载体缺 `role` 时补协议必需的 `developer`，不新增消息。
2. **保留官方兼容通道。** 两个桌面入口都使用同一原生安装。官方模型直接发往 OpenAI，不经过 211 API 网关，不进入非 GPT/Chat 转换。官方入口使用原生官方目录，API 入口提供合并目录。
3. **保持同一对话恢复。** 保留旧 `smr` / `chatgpt_api_launcher` provider 定义；转换发生在发出的副本中。第三方思考及本地临时思考 ID 转为原文 summary，不冒充官方服务端 ID；官方加密状态原样保留。移除原先额外添加的思考说明前缀。
4. **补齐媒体字段。** Chat 内联 WAV/MP3 音频映射为 `input_audio.data/format`；API 路径中的 ChatGPT 图片 file_id 从原生只读文件服务取得原下载 URL。原历史保留 file_id，切回官方时恢复原生引用。取消请求也取消附件解析。
5. **保留原有行为。** 未调整模型思考档位，未加入网络重试，未修改代理/SSH/211 服务配置、登录文件、客户端语言或功能开关。已有有界上下文恢复逻辑保留。

完整字段规则见 [消息转换协议](message-protocol.md)。

## 如何解读测试结果

- **真实模型：** 请求实际经过修改后的适配层和真实上游。原生工具与压缩测试运行安装的原生 app-server。
- **原生受控：** 安装的原生 app-server、实际本地工具、实际启动器配置与实际适配层；模型端点由可重复的测试服务返回有效协议。用于区分转换错误和模型是否愿意正确调用工具。
- **协议回归：** 比对请求、响应、事件和历史字段；证明转换保持数据，不能证明某个模型理解图片或某个插件的远程业务成功。
- **排除：** 网络/服务不可达、模型不具备能力、思考强度、模型自己输出错误、官方客户端本身不支持的能力。排除项不记为通过。
- **未端到端执行：** 明确列出，不能归到“已全部验证”。

## 官方模型与混合历史的真实验证

官方原生通道的 `gpt-6-luna` 已完成预热后连续三次工具调用：工具仅在最初 additional_tools 中声明，后续请求仅含 previous_response_id 和增量输入。这覆盖本次“第一轮有工具、后续称没有工具”的具体故障。

当前官方目录中其他 8 个 ID（gpt-6-astra、gpt-6-sol、gpt-reserve、gpt-5.6-sol、gpt-5.6-terra、gpt-5.6-luna、gpt-5.5、codex-auto-review）在这组测试中遇到 TLS 连接中断，未记为通过。网关 GPT 的验证结果与官方账号通道分开统计。

真实混合历史测试发现旧 additional_tools 缺少 role，修复后对 `词元计划/glm-5.3-flash` 和 `阿里云订阅/deepseek-v4.1-flash` 重新验证：官方 → 网关及网关 → 官方均通过，能够复述上一模型实际生成的随机内容。其他组合另有 225 组协议组合测试，以及全部 14 个模型的原生受控同对话切换测试。

旧 `smr` 与 `chatgpt_api_launcher` provider 各有一组原生重开恢复测试通过；没有通过改 threadId 或复制对话来绕过问题。

## 生效情况与剩余边界

程序已更新在实际安装目录，本机 8102 端口的兼容服务已启动并核对构建为 `fbc9d667c38f6b827f9e86108f93a1142453f1a096122b065cbff6500f56f34d`。健康检查识别 14 个网关模型、9 个官方目录项；网关可用，官方目录本次刷新遇到 TLS 中断，继续使用已有目录。

本次未强制关闭正在使用的客户端。启动器的两入口配置将在**完全退出客户端，再从任一桌面入口重新打开**时应用；不能把启动了新兼容服务等同于旧客户端进程已经重新加载配置。真实 config.toml / auth.json 的内容在测试期间保持不变。

英文、无 ultra、旧布局外观同时出现的共同原因是原生在线功能配置初始化失败后的默认分支；登录提示另有原生账号发现超时。按要求未补网络重试、改原生客户端或硬编码 UI 开关。没有承诺这两个网络相关现象因此消失。
