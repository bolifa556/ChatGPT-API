# 上下文容量与连接设置

## 容量规则

API 模型分别配置上下文窗口。新模型使用接口信息、已确认规格或已有检测结果中的容量。无法确认时，容量和初始配置统一设为 **262,000 tokens**，之后可手动修改。客户端通常预留 5%，控制台在同一列显示配置窗口和有效窗口，例如 **500K → 475K**。

容量记录按 API 基础 URL 和原始模型名保存至 `data/cache/model-contexts.json`，与来源显示名及公开模型别名无关。优先采用部署元数据（例如 vLLM 的 `max_model_len`），其次已核对规格与官方最大窗口。默认容量记录使用 `default-context-window` 来源，后续接口提供容量时可更新。

控制台的“当前配置”和“已知容量”支持点击编辑，单位为 K。配置窗口按填写值写入 API 模型目录，用户可以填写高于已知容量的数值。纯图片模型的当前配置用于选择默认生图模型。

原生客户端自行根据模型窗口推导压缩阈值。适配层不另写摘要，不注入压缩提示词，不创建额外消息。

## 生效时间

保存后完全退出原生客户端，再打开对应入口，加载新的菜单与上下文。模型切换后的用量浮窗随客户端新一轮统计更新，不保证点击菜单时立即刷新。

同一对话的官方 / API 模型传输可以切换，但原生 provider 的压缩方式需退出重开后同步。官方 provider 使用官方远程压缩，自定义 provider 使用原生自定义通道的压缩。只有加密压缩块而无可读历史时，不能保证非 GPT 模型继续处理，会明确报错。

## API 不可用

启动检测到自定义 API 不可用时，可重新打开 URL / Key 设置。取消保留原配置，完成后更新配置再准备目录。多来源目录分别处理，单个来源失败不阻断其他可用来源。

新增来源保存后会自动刷新目录并检查新模型。容量从目录信息、已有规格和保存结果中读取。GPT 模型使用官方档位。其他模型缺少能力声明时，进行一次参数校验，读取模型明确返回的档位列表，最多四个模型并行。校验返回的别名说明会排除，通用枚举错误标为未知。每项只校验一次，缓存只保留最终容量和可用档位列表。
