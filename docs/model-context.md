# 上下文容量与连接设置

## 容量规则

默认 API 全局上限为 **500,000 tokens**。客户端通常预留 5%，因此浮窗显示约 **475k**；官方模型始终使用原生目录中的设置。

容量记录按 API 基础 URL 和原始模型名保存至 `data/cache/model-contexts.json`，与来源显示名及公开模型别名无关。已经确认容量后，后续模型目录刷新不再次额外探测容量。优先采用部署元数据（例如 vLLM 的 `max_model_len`），其次已核对规格与官方最大窗口。未提供容量的模型标为未知，使用兼容模板，不把模板默认值宣称为模型实际容量。

控制台的“模型与上下文”可设置全局或单模型上限，范围为 4,096 至 2,000,000。最终目录窗口取已知实际容量、单模型选择和全局上限中的较小值；单模型留空为自动。手填未知模型的容量不能增加上游实际能力。纯图片模型没有聊天上下文，不提供容量编辑。

原生客户端自行根据模型窗口推导压缩阈值。适配层不另写摘要，不注入压缩提示词，不创建额外消息。

## 生效时间

保存后完全退出原生客户端，再打开对应入口，加载新的菜单与上下文。模型切换后的用量浮窗随客户端新一轮统计更新，不保证点击菜单时立即刷新。

同一对话的官方 / API 模型传输可以切换，但原生 provider 的压缩方式需退出重开后同步。官方 provider 使用官方远程压缩，自定义 provider 使用原生自定义通道的压缩。只有加密压缩块而无可读历史时，不能保证非 GPT 模型继续处理，会明确报错。

## API 不可用

启动检测到自定义 API 不可用时，可重新打开 URL / Key 设置。取消保留原配置，完成后更新配置再准备目录。多来源目录分别处理，单个来源失败不阻断其他可用来源。

控制台刷新只请求 `/models`，不测试模型生成、不重复执行聊天；运行期间没有定时目录轮询。网络和模型自身限制按上游实际错误呈现，不添加生成重试。
