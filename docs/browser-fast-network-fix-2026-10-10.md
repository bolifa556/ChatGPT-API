# 浏览器、Fast 与网络修复记录

2026-10-10，北京时间；启动器版本 3.0.6。检查当前 Windows 桌面安装和原生内核 `0.162.0-alpha.2`，测试消息转换使用隔离上游，不访问用户的聊天正文。

## 已应用的改动

1. Chat Completions 转 Responses 时保留上游实际返回的 `service_tier`。JSON 与流式响应规则一致；流的最后一块才返回档位，或上游从 `priority` 退回 `default`，也会反映在最终响应中。字段缺失时不编造档位，显式 `null` 保留。
2. 网关模型目录只采用该网关 `/models` 提供的 `service_tiers`、`additional_speed_tiers`、`default_service_tier`。没有声明时清空从官方模板继承的速度选项，不再给自定义模型复制“1.5x speed”等未经上游确认的描述。官方模型元数据保持原样。已有请求里的 `service_tier` 继续转发；展示声明与请求转发分别处理。
3. 补充纯 API 用户的原生内核回归验证：不创建官方凭据，不要求先登录，再验证本地工具、文本压缩、模型切换和恢复。Windows 混合模式与 Linux provider-only 继续共用同一消息转换核心。

产品改动只涉及档位元数据与目录；没有增加系统提示词、改写原始历史、创建替代浏览器、修改官方客户端或增加网络重试。本机两个桌面入口均指向当前安装目录；适配服务已加载当前源码。客户端菜单在启动时加载，完全退出后重开可加载新目录。

## 分情况处理

| 情况 | 模型及认证 | 工具和其他功能 |
| --- | --- | --- |
| 有官方登录，选择官方模型 | 保留原生官方 provider、凭据和 Responses，兼容通道发往 OpenAI | 由原生客户端提供；官方压缩遵循原生 provider。官方接口网络或账号权限失败不能由消息转换补齐 |
| 有官方登录，选择自定义模型 | 只向网关使用 API Key，转换模型需要的请求与返回格式 | 使用客户端提供的相同工具。文本压缩、历史和切换遵循现有原生机制；浏览器工具自己的官方身份请求独立出网 |
| 没有官方登录，仅自定义 API | `requires_openai_auth = false`，API Key 只用于网关，不伪造官方身份 | 本地终端、文件编辑、本地 MCP、文本压缩、取消、继续和自定义模型之间切换不需要官方凭据。依赖官方账号权限的原生服务不能凭网关 Key 获得 |
| 自定义 API 生图 | 无登录只请求 API 生图模型；有登录时沿用既有官方优先与明确不可用时回退策略 | 既有生图协议回归通过；没有对应模型明确报错，不补写提示词，不因网络错误重新生成 |

同一已加载对话的 provider 与压缩方式仍由原生客户端决定。沿用既有退出重开后的 provider 同步机制，未实现会清空执行器状态的静默热切换。官方加密压缩历史不能无损变成第三方可读上下文；这类限制不通过删除历史掩盖。

## 浏览器及网络结论

浏览器工具的名称、namespace、代码字符串、中文参数、整数超时、历史 `call_id` 和返回内容，在已测转换路径中均正确。24 个目录模型的 30 种固定协议情况，以及官方 GPT、网关 GPT、非 GPT 的 HTTP / WebSocket 共 6 条转发路径通过。这里验证转换，不表示每个真实上游都执行过浏览器任务。

内置浏览器已在本机规则模式、TUN 关闭后实际完成本机页面的中文输入、勾选、点击和截图。这是在当前有官方登录的桌面会话中验证，不能当作无登录浏览器服务的完整验证。此前检查还覆盖本机页面跳转、后退、前进；没有据此承诺所有外部网页可访问。

当前原生 Edge 扩展运行时在操作前需要请求 `https://chatgpt.com/backend-api/aura/identity`。工具进程直接连接公网，不自动采用适配层的官方代理；该请求不经过 `/v1/responses`。只设置模型转发代理不能解决这一独立链路。隔离配置探测也确认：插件级配置的 `env` 不生效；根级同名 MCP 配置必须提供完整命令，并会替换内置服务器。因此没有通过覆盖内置 MCP 来冻结其启动参数、绕过插件管理或伪造官方身份。

为诊断曾短暂启用本机 TUN；当时官方身份请求与 Edge 操作成功。按用户要求已完整恢复为：

- Mihomo 运行模式 `rule`，`tun.enable = false`；
- Clash 的 `verge.yaml`、`config.yaml`、`clash-verge.yaml` 持久设置均为 TUN 关闭；
- 系统代理保持 `127.0.0.1:7897`，Meta 虚拟网卡已移除；
- 原代理组和规则保留，没有手动改动系统 DNS 或 hosts。

最终复核发现 Clash 内存中的旧基础配置在一次重启时留下了 TUN 开启值，运行时与生成配置仍是关闭。已再次清除三个文件中的残留，重启 Clash/Mihomo 使其重新读取关闭配置，并重新验证：运行与持久配置均关闭、模式为 rule、系统代理启用且仍为 127.0.0.1:7897、Meta 网卡不存在。未重启原生 ChatGPT 客户端。

在恢复规则模式后的独立对照中，官方模型目录直连、显式 7897 代理、8102 适配通道，以及浏览器身份直连和代理均出现约 10.7 秒连接超时。此前同一显式代理与适配通道也曾返回 200，说明网络状态会变化；Clash 日志另有真实链式节点超时与远端断连证据。当前 502 是适配层报告上游连接失败，不能据此认定消息转换出错。Edge 在新的工具运行时中仍出现 `nodeRepl.fetch request failed`，未获得不使用 TUN 的持久恢复结果。

**仍未解决的是原生浏览器的独立出网与当前代理节点连通性。** 本版不启用 TUN、不替换原生浏览器、不修改原生插件，也不增加重试。无官方登录时，当前浏览器扩展依赖的官方身份权限还构成独立限制；不能保证所有官方账号服务在纯 API 模式中可用。

真实上游的推理能力、工具参数生成正确性、速度、计费、官方账号服务权限和当前网络可用性不由隔离回归证明。保留这些边界，不将受控接口通过写成“所有真实功能均通过”。

原生模型验证示例：设置 `CODEX_CLI_PATH` 为当前客户端内核，设置 `EXTENDED_NATIVE=true` 后运行 `tests/native-switch-test.mjs`；另设 `NATIVE_API_ONLY=true` 验证纯 API。`NATIVE_SWITCH_REPORT_NAME` 可指定结果文件名。模型取自当前目录的 `gatewayIds`。测试只在 `data/testing` 的独立目录执行，不向用户聊天添加消息。逐模型结果在本机 `data/diagnostics/native-mixed-3.0.6-result.json` 和 `native-api-only-3.0.6-result.json`，不随发布包分享。
