# 功能修复及最终边界

2026-10-11，北京时间。当前版本 3.0.8，Windows 原生客户端仍为 `26.1002.7124.0`，内核 `0.162.0-alpha.2`。

## 本次修复

纯 API 模式下，图片 `file_id` 不再尝试通过本机残留的官方登录访问 ChatGPT 文件服务。Responses 本身可以携带 API 上传所得的文件 ID，因此保留 ID、`detail` 和历史原文交给该 API，不猜测文件归属或编造图片内容。必须转成 Chat 格式时，只有文件 ID 而没有图片数据/URL 的请求沿用明确的格式错误；本地图片数据与图片 URL 正常转换。有官方登录的混合模式继续解析客户端的 ChatGPT 图片引用，官方模型仍保持原始文件 ID。

这项改动与先前 Fast 修复共用 Windows、Linux 的消息转换核心。没有新增提示词或聊天记录；没有修改原生客户端、原生浏览器代码或插件注册；没有新增网络重试。模型列表、登录、工具审批与浏览器权限仍采用原生机制。

维护文档已更正原生回归参数：`EXTENDED_NATIVE=true`、`NATIVE_API_ONLY=true`、`NATIVE_SWITCH_REPORT_NAME`。模型从当前 `gatewayIds` 读取。

## 仍然无法由适配层修复的项目

**原生 Edge 扩展独立出网。** 重新初始化并枚举原生工具时，Edge 仍在页面操作前返回 `nodeRepl.fetch request failed`；同一轮内置浏览器本机页面可操作。本机原生源码显示，外部浏览器会调用 `https://chatgpt.com/backend-api/aura/identity`，还用该身份初始化浏览器请求头策略。这些请求不经过适配器的 `/v1/responses`。

隔离原生内核测试确认：只给父进程设置代理不够，MCP 默认过滤代理环境变量；完整同名根级 MCP 配置会替换官方插件注册，不能仅追加 `env`。原生启动代码只向内置 CUA 传递特定环境字段，未发现可以只添加代理又保留动态插件注册的受支持入口。原生的 `BROWSER_USE_DISABLE_AMBIENT_NETWORK` 也不能完整解决外部浏览器的身份依赖；没有启用用于本地测试的安全检查绕过选项。

因此本次没有用覆盖原生插件、修改原生代码或开启 TUN 来宣称 Edge 已修复。原生客户端的代理传递需要由官方提供稳定入口/修复，或者放宽当前“不修改原生客户端、不使用 TUN”的约束；目前 Edge 未通过。这是本机实测结论，公开报告中的绕行方法没有被当作官方支持的部署方案。

已只读检查本机另一个 `26.1007.2314.0` 客户端目录。它的启动代码仍构造指定的工具环境变量列表，没有发现追加代理的配置入口；浏览器/Rust 组件与当前运行版本有变化，CUA 启动脚本相同。该版本不是当前运行且注册的客户端，未实际启用或验证，所以既不能声称它已修复，也不能仅凭静态代码声称它一定无法修复。

**纯 API 的官方账号服务。** 匿名访问上述身份接口返回 401。网关 API Key 不是 ChatGPT 官方身份；无法通过消息转换赋予官方浏览器账号服务、官方云功能或私有文件访问权限。纯 API 本地工具、文本压缩及支持相应接口的自定义模型仍可使用。官方账号/权限缺失与模型本身无能力按用户要求分别记录，不伪造身份或内容。

同一已加载会话的 provider 与压缩方式仍由原生客户端决定；退出重开后的原生 provider 同步机制沿用原实现，没有引入会清空跨轮执行器状态的隐式热切换。
