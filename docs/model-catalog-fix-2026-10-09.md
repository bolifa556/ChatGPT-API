# 客户端更新后的模型目录加载错误

修复版本：3.0.4。检查客户端：Windows OpenAI.Codex 26.1002.7124.0，原生内核 `codex-cli 0.162.0-alpha.2`。

## 原因与范围

本机错误为：`GPT/gpt-5.6-terra` 缺少 `base_instructions` 和 `model_messages.instructions_template`，导致整个自定义模型目录无法加载。

原生缓存中的官方模型采用 `model_messages.instructions_template`，没有旧字段 `base_instructions`。启动器为网关 GPT 别名复制对应官方模型后，却统一把 `model_messages` 设为 `null`。因此两个目录中的 4 个 GPT 别名都缺失原生客户端要求的指令信息：

- `GPT/gpt-5.6-terra`
- `GPT/gpt-6-astra`
- `GPT/gpt-6-luna`
- `GPT/gpt-6.1-sol`

这是启动器目录生成的问题，在本地配置解析阶段发生，尚未调用网关推理接口。官方目录记录本身有效，其他 10 个网关模型保留既有 `base_instructions`，也通过该项校验。

官方目录可能同时提供两个字段，也可能只有 `model_messages`；不能依赖重新下载目录后刚好出现旧字段来修复问题。

## 修改

`src/shim.mjs` 只对非 GPT 模型保留既有的 `model_messages: null` 转换。网关 GPT 别名保留复制来的完整官方对象，包括模板、变量、持久指令及其他原生字段；找不到对应官方名称时，也保留现有回退模板的这些字段。

不新增指令，不把模板复制到另一个提示词字段，不修改客户端二进制、登录、设置或聊天记录。官方原始模型记录不改动，既有非 GPT 消息适配保持不变。Windows 和 Linux 使用同一段目录生成逻辑。

本机两个生成目录已备份并重新生成。原生版本检测现已得到当前内核版本 `0.162.0`；版本解析与路由逻辑无需修改。

## 验证

- 模型目录回归：新旧指令结构、对应名称继承、未知 GPT 别名回退、完整嵌套元数据保留、两个菜单一致，及原有刷新、认证、并发、304/错误行为通过。
- 9 组现有协议回归通过，覆盖工具、历史、模型切换、图像、生图、HTTP/SSE/WS 等适配；这不是所有远程模型能力的重新验收。
- Windows 启动器测试通过。
- 使用当前原版内核，在隔离配置目录调用 `config/read`，成功复现修复前的缺失指令错误；修复后的混合目录 24 个模型、网关目录 14 个模型均通过配置加载和 `model/list`。另将官方记录与 GPT 别名的旧指令字段移除，仅保留官方 `model_messages`，24 个模型仍通过。
- Windows 3.0.4 独立安装包通过安装、保留配置更新、损坏校验、快捷方式、语法与依赖检查；Linux x64 / arm64 两个包通过清单、校验和、源码一致性及架构检查。Ubuntu 22.04 中实际运行 Linux x64 包，通过目录回归和 8 项 provider / 安装验证；arm64 未做运行验证。
- 修复与验证前后的本机 `auth.json` 和 `config.toml` SHA-256 一致。两个现有桌面快捷方式仍指向已经修复的安装目录。

原生验证不创建对话、不请求推理，也不重启已有客户端或工具会话。本机诊断结果位于 `data/diagnostics/native-catalog-result.json`。

## 使用

已报错的客户端可在目录修复后点击“重试”。如果对应启动器已经退出，重新打开桌面入口，让它重新启动本地路由。其他电脑使用 3.0.4 独立发布包更新原安装目录；安装器保留原配置与个人数据。

原生配置入口说明：[官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。`model_catalog_json` 指定启动时加载的 JSON 目录；上述具体字段故障由本机目录与原生配置解析验证确认。
