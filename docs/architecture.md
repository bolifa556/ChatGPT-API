# 路由与兼容机制

```text
桌面快捷方式 → 根目录 VBS 入口 → Launch-ChatGPT.ps1
  原生入口 → 本地兼容通道 + 原生官方目录 → 系统注册的桌面客户端
  API 入口 → 判断已保存登录 + 本地兼容通道 + 合并目录 → 同一桌面客户端
  API-only 入口 → API Key + 本地兼容通道 + 网关目录 → 同一桌面客户端

客户端模型请求 → 127.0.0.1:8102
  官方模型 ID → 官方接口，使用客户端或本机的 ChatGPT 凭据
  网关模型 ID → data/providers.json 中对应来源的 URL / Key

安装目录的控制台入口 → 本机随机端口控制台 → data/providers.json
  多个启用来源 → 并行 /models → 独立缓存 → 原生合并目录
```

## 控制台与多个来源

控制台使用包内 Node 的 HTTP 服务和静态页面，无新增依赖。服务只监听 `127.0.0.1`，校验连接令牌、Host 与 Origin，页面没有外部脚本。状态接口不回传保存的 Key；写入使用修订号防止多窗口覆盖，文件以原子替换保存。控制台保存不重启客户端，菜单、来源与上下文在客户端退出重开后应用。

`data/providers.json` 保存来源与上下文，未创建时从 `.env` 导入默认来源。`.env` 保留本机桥接启动凭据，运行中不随控制台保存而更换；各远程请求使用选中来源的凭据。新增来源公开 ID 为 `@来源ID/原始模型ID`，默认来源保持旧 ID。路由在异步执行前固定 URL、Key、dispatcher 与上游模型名；转换器只读取原始模型名，响应恢复公开 ID，不把来源前缀送给上游。

每个来源按 URL / Key 指纹保存独立的 24 小时目录缓存；一个来源失败不阻断其他来源，不跨来源借用缓存或自动切换聊天模型。API 入口启动和显式刷新时查询 `/models`，没有定时查询；容量记录按真实 URL / 原始模型 ID 保存，确定后不额外重复探测。

## 传输

官方线路沿用现有环境或 Windows 系统代理，不配置 VPN。网关默认按填写的 URL 直连，也支持显式选择 SSH 隧道。无需另部署服务器端兼容服务。

网关不接收官方 OAuth 凭据或账号头。官方请求不会用网关 API Key 代替登录。

官方 Codex HTTP 请求缺少原生传输压缩时，由适配层补充无损 zstd；已经压缩且不需要格式转换的请求保留原始字节。网关接口不默认启用请求压缩。模型生成、上下文压缩和生图请求不设置适配层响应头／响应体等待超时，保留客户端取消、上游结束及连接错误；连接建立、目录查询和文件下载仍有各自的期限。Responses 完成事件或 Chat 的结束标记会释放对应 HTTP 流，包括压缩流，不等待上游另外关闭连接。

`route-state.json.entryMode` 保存当前入口范围：`official` 仅官方，`api` 依据登录状态，`apionly` 强制网关。API Key 助手从活动入口读取选择，避免在 API-only 模式下因发现保存的 OAuth 而重启混合路由。官方入口不查询网关目录、不向网关发送模型请求，生图失败保留官方错误；API-only 不请求官方目录、模型或图片文件服务。官方登录文件始终由原生客户端管理。

启动器在启动时刷新模型目录，不做每分钟轮询，生图请求也直接使用本次启动取得的网关目录。官方目录查询使用当前已安装内核的实际版本，由匹配安装包哈希的原生可执行文件 `--version` 取得，写入启动器自己的 `route-state.json`。旧 `models_cache.json.client_version` 仅描述历史缓存来源，不能作为当前版本，也不使用写死的版本兜底。原生客户端带 `client_version` 的 `/models` 请求仍按原查询、认证和响应转发，保留官方字段、ETag、304 与错误；成功的响应同步本地目录。显式的 `/readyz` 仍可刷新目录，供启动时复用路由和诊断使用；后续查询沿用客户端实际请求版本，直到下一次安装版本变化。同步目录时同时写入 API 菜单文件，内容未变时不重写。原生自定义目录在启动时加载，磁盘更新不代表运行中的菜单已重载。

API 入口根据启动时选中的模型选择提供方：官方模型使用 `openai`；网关模型使用 `chatgpt_api_mixed`，以 `requires_openai_auth=true` 保留客户端账号认证，并选择客户端内置文本压缩。官方入口默认 `openai`。传输目标继续只由模型归属决定，活动会话中的提供方切换还需重新加载。

客户端的网关 WebSocket 请求转换成 HTTP SSE；官方 WebSocket 保留协议。跨服务续聊使用连接内缓存的上下文，不把另一服务的 response ID 直接提交。连接缓存最多 64 份、合计 256 MiB，共用历史项目按引用计数，断开即释放。无法重建上下文时返回明确错误。

## 消息、工具和思考记录

网关模型完整继承原生 `model_messages` 或旧版 `base_instructions`，由客户端按权限、工具和协作模式组装指令，不替换成适配层自写提示词。实时／本地原生目录优先；全新 API-only 环境使用包内的原生模板快照，来源版本记录在 `assets/model-template.json.source`，发布时通过原生 CLI 校验。模板快照只替换指令字段，保留既有兼容能力设置。自定义工具只转换参数 Schema、原始描述及原始 grammar，不附加纠错指令。

- 合法的 GPT 原生消息按原格式发送；历史中不合规的项目 ID 在请求副本中修正。
- 官方 `input.additional_tools` 保持原位，使后续原生增量请求能继承工具；仅旧工具载体缺少角色时补必需的 `developer` 字段。面向无状态网关的完整请求才提取到顶层 `tools`。
- 非 GPT 模型统一关闭 `use_responses_lite`，将命名空间、原生自定义工具及工具结果转换成网关支持的普通函数调用，再将响应还原给客户端。
- GPT 可用的原生加密思考继续保留；第三方明文思考进入官方通道时改用原文 `summary_text`，不发送第三方私有 ID。跨非 GPT 模型的可读思考按原有上下文形式转换，移除原先额外添加的“先前思考”前缀。
- GPT 加密压缩块没有可读上下文时明确报错，避免默默丢失上下文。
- 非 GPT 返回的思考 ID 标记来源，避免再切回 GPT 时误当成官方加密状态。
- 同模型思考按来源标记保留；词元使用标准 Chat reasoning_content，阿里云仅结构化输出请求切换为 Chat response_format，其他请求保持 Responses。
- 官方 Responses Lite 的完整项目从 output_item.done 收集；最终 output 为空时仍保留真实历史。增量工具和最终项目使用一致的 ID，不合并不同项目的字段。
- API 请求中的 ChatGPT 图片文件 ID 通过原生只读文件服务换成原下载 URL，原历史仍保留文件 ID。附件解析与模型请求共用取消信号；Chat 内联音频只转换数据字段，不转写或生成内容。

完整字段映射、压缩边界与逐模型路由见 [消息转换协议](message-protocol.md)。

这些消息转换仅发生在请求与响应副本中，不改写保存的聊天内容。启动器另在桌面应用未运行时，用原生 `thread/resume` 双向匹配已知对话的模型和提供方：网关模型的旧 `openai` 绑定改为网关提供方，官方模型的旧网关提供方恢复 `openai`。原生客户端自行保存设置事件和数据库元数据，同一 threadId 与原有消息保持不变。修复程序不直接编辑 rollout 或数据库，不发用户消息，不触发压缩或工具执行。

非 GPT 请求含远程 v2 的 `compaction_trigger` 时，适配层明确拒绝并提示退出重开完成绑定修复，不将其发给普通模型。官方请求中的同类控制项目继续按原协议转发。格式兼容不能补足上游模型能力，也不能消除原生前端对官方 provider 的功能限制。

## 文件对应

| 文件 | 职责 |
| --- | --- |
| `src/shim.mjs` | HTTP/WS 路由、认证隔离、模型缓存、流式响应 |
| `src/settings.mjs` | 多来源配置、稳定模型标识、原子保存与脱敏 |
| `src/gateway-sources.mjs` | 多 URL 目录发现、独立缓存和请求来源选择 |
| `src/console.mjs`、`assets/console/` | 本地控制台服务与静态界面 |
| `src/transport.mjs` | 原始压缩数据转发、异步编解码、连接超时、取消与流式背压 |
| `src/response-state.mjs` | 请求队列与有界连接内历史引用，不持久化聊天副本 |
| `src/non-gpt-compat.mjs` | 非 GPT 消息及工具映射 |
| `src/chat-compat.mjs` | 指定上游的 Responses/Chat 双向转换 |
| `src/history-compat.mjs` | 思考上下文保留、跨模型 ID 修正 |
| `src/sse.mjs` | SSE 解码、压缩流、Unicode 分片 |
| `src/Launcher-State.ps1` | 登录判断、临时配置和恢复 |
| `src/repair-thread-providers.mjs` | 通过原生会话 API 更正旧网关对话的 provider 元数据 |
| `src/Router-Control.ps1` | 路由进程复用、启动与就绪检查 |
| `src/Package-Paths.ps1` | 数据位置与旧版一次性迁移 |
