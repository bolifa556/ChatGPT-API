## 生图与编辑兼容修复

- Responses 返回的 `image_generation_call` 转为聊天中可显示的图片，保留 PNG、JPEG、WebP 原图。HTTP、SSE、WebSocket 使用同一转换，支持多张图片、文字混排和重复事件。
- 发送后续历史时，将适配层的图片展示消息还原为原始生图结果，修复 `Invalid value: 'input_image'`。兼容此前已经保存的图片消息，不改写聊天历史，不添加用户消息或虚构工具调用。
- 原图保存在客户端数据目录的 `generated_images/chatgpt-api/`；原始 ID、图片描述等元数据保存在旁边的小型 `.response.json` 文件中。重新打开对话后仍可引用原图编辑，缺少旧元数据文件时也能使用已保存的图片。
- 图片编辑默认保留客户端 JSON 格式；当接口明确拒绝图片字段时，在同一 API、同一模型上转换为 multipart 文件上传一次，保留提示词、原图、遮罩和显式参数。网络、权限、内容拒绝、无效图片及已经返回图片的情况不触发此转换。
- Responses 图片流事件上限与非流式响应统一为 64 MiB，修复较大图片被 16 MiB 文本事件上限截断的问题，并避免接收图片时反复扫描整个已接收事件。工具参数上限保持不变。
- 图片 URL 返回通用二进制类型时，按 PNG、JPEG、WebP 文件签名识别。下载不携带 API Key 或官方登录凭证。

本次只调整必要的消息与图片协议转换，不增加依赖、MCP、提示词、额外聊天或网络重试，不修改官方客户端。

## 验证与边界

真实 Bifrost / GPT 通道已完成一次生成和一次原图编辑，返回图片均能解码；后续工具图片上下文也已得到正常回答。严格模拟接口覆盖原始 400、HTTP/WebSocket 续聊、模型切换、重新连接、压缩输入、多张图片、较大图片、下载和错误返回。官方客户端内核在隔离环境中完成了两张图片与文字的保留、重新载入对话、选择最近图片继续编辑。

其他用户电脑上的原始请求及桌面界面不在本机，不能据此保证其所有上游服务都正常。兼容图片以聊天图片呈现，不保证官方图库和进度卡片等专用界面完全一致；已有空白历史不会自动重写。模型能力、图片接口权限以及跨入口/压缩限制见项目 [README](../../README.md)。
