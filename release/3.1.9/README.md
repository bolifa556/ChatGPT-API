## 本次修复

- **原生生图链路**：经 Bifrost 使用 GPT 网关模型时，将客户端已有的原生 Responses 协议标记传递给上游，防止 CLIProxyAPI 自动添加客户端未声明的托管生图工具。生成、保存、继续编辑及图片展示由客户端原生 `image_gen` 处理。不拼接最终文字、不删除空答复、不重排消息，也不修改官方客户端。
- **非 GPT 配置更新**：将客户端历史中的 `configuration_update` 按顺序转换为目标接口的当前请求参数，保留最后生效的设置。结构化输出根据转换后的格式选择接口；官方和 GPT 通道继续原样发送配置记录，保留原生缓存语义。
- **MCP 工具选择**：远程工具与本地工具同名时，不再错误映射成本地函数；允许工具列表按 MCP 服务器区分。目标 Chat 协议无法表达的单个远程工具限制会明确报错，不扩大允许调用的范围。

3.1.8 的原图保存、图片历史回传、旧版图片编辑接口、较大图片流和下载兼容继续保留。本次没有增加依赖、MCP、提示词、额外聊天或网络重试。

## 协议检查

| 范围 | 检查内容 |
| --- | --- |
| 消息与历史 | 角色、阶段、文字及空白、工具调用 ID、同模型思考、原生不透明字段；官方与网关切换共 225 组模拟组合 |
| 工具与 MCP | 自定义工具原始输入、命名空间、动态工具目录、参数与结果、并行设置、指定工具与允许列表 |
| 配置及结构化输出 | 原生配置记录、连续更新与恢复文本格式、JSON Schema、当前请求参数与接口选择 |
| 图片与附件 | 原生图片结果、后续编辑、历史回传、多模态工具结果、图片 URL、音频数据、文件数据及无法表示的引用 |
| 流式与连接 | HTTP、SSE、WebSocket、分块及重复事件、Responses Lite 终态、错误、取消、中断、重连与完整上下文恢复 |
| 压缩 | 官方配置及原生压缩项透传、压缩请求中的图片历史；跨厂商不能解读的不透明上下文明确报错 |

协议测试使用严格模拟接口，并核对当前官方客户端内核与实际返回数据；这不等同于对每个上游模型的全部能力作保证。

## 实际验证与边界

- 隔离的纯 API 环境中，当前官方客户端内核与真实 Bifrost 通道完成一次生图和一次原图编辑。两次均产生原生 `imageGeneration` 结果项，尾部空的 `final_answer` 保持原样；未使用模拟界面或修改客户端。
- 四个 GPT 网关模型通过工具调用、历史续聊和结构化输出检查。原生 `configuration_update` 在当前 Bifrost 2.4.0 通道也已正常完成请求；本次没有升级或重启服务器。
- 词元计划三个模型的工具调用通过；该轮结构化输出测试的上游只有思考字段、没有正式正文，适配层保留了这些字段，未将思考改成最终答复。
- 阿里云订阅六个模型当前返回访问权限拒绝，未计为实测通过。vLLM 及其他兼容协议纳入模拟转换检查；未对未配置的真实服务器作验证。
- 其他上游如果自行添加工具、丢弃原生字段或只返回思考内容，仍需修复对应服务。客户端未注册的工具、模型本身不支持的能力及网络问题，不能通过制造消息解决。旧的已折叠图片历史不会自动改写。

## 安装与更新

完全退出客户端后安装到原目录，保留 `data/` 与客户端数据目录，再从相应入口打开。Windows / macOS 提供三个聊天入口和控制台；Linux 提供 API 入口与控制台。默认生图模型继续自动选择，也可在控制台更改。

安装包包含运行时和锁定依赖，不含个人 Key、登录、聊天或日志，不提供独立下载校验文件。macOS 仍为 ad-hoc 签名，未经过 Apple 公证，保留系统正常的手动允许流程。完整使用说明见项目 [README](../../README.md)。
