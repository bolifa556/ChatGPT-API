## 本次更新

- 兼容新版原生客户端的对话 provider 绑定。三个入口默认共用 `chatgpt_api_launcher`；官方入口只发送官方模型请求，并保留原生远程压缩。旧对话可在控制台“使用说明”选择其原绑定，不改写聊天或创建副本。
- GPT 模型的 Fast 沿用客户端速度菜单，保留开启及关闭后的原生服务档位；非 GPT 模型不展示 Fast，控制台不增加第二个开关。补齐经 Bifrost 转发的客户端协议、版本与回合元数据，不复制官方账号凭证到 API 来源。
- 生图按控制台选定的来源与默认模型发送，保留原生请求明确指定的画质和实际返回结果，不增加降档错误或重复生成。官方生图通道仍原样转发。
- 控制台强度统一使用英文档位；图片思考与画质并排显示，增加“生图模型来源”说明，移除“自动使用最高档位”和“模型默认”菜单项，未选择时仍采用可确认的最高档位。
- 未配置 API 时可单独保存官方入口的历史兼容选择；退出时恢复原配置并保留用户期间修改的其他设置。

## 模型强度与生图设置

- “模型与上下文”表末尾增加“思考强度”列，列出可确认的模型档位；缺少信息时显示“无法检测”，明确不支持时显示“不支持”。
- 依据接口声明、匹配的官方目录和准确型号的官方规格自动识别。接口声明优先，不按模型类型随意套用其他型号的档位，不发送生成请求逐档试错，也没有定时轮询。
- 图片的思考复杂度和画质分别选择，默认使用可确认的最高档位，按 API 来源及模型独立保存。未知或不支持的图片复杂度不继承客户端原模型的设置，避免把 `complexity: max` 直接发给不兼容模型。普通聊天思考设置不变。
- 删除表格上方的默认生图提示行；在“所有来源”右侧选择“官方生图设置”或“自定义生图设置”。表格和菜单沿用控制台风格，模型区正文与控件统一为 13px。

| 使用方式 | 生图行为 |
| --- | --- |
| 登录后的 API 入口，选择官方 | 使用订阅账号；请求、参数和错误按官方格式原样转发，不自动转到自定义模型 |
| 登录后的 API 入口，选择自定义 | 使用表格中选定或自动选好的 API 生图模型，并应用该模型的强度设置 |
| 纯 API 模式 | 忽略保存的官方选项，始终使用自定义生图设置 |
| 原生官方入口 | 始终使用官方生图通道 |

## 检查范围与边界

覆盖模型能力解析、未知能力、来源隔离、设置保存、默认最高档位、原生参数转换、官方原文保留、官方／自定义通道和纯 API 例外；同时保留原有消息、历史、工具、流式、生图编辑和网络兼容回归。控制台另做浏览器交互和外观检查。

官方型号规格不能证明第三方别名或改造后的服务完全一致；实际接口声明优先。没有提供能力信息、名称又不能准确对应规格的模型会显示“无法检测”。本版不修改客户端，不改提示词或聊天历史，不增加依赖、网络重试或运行时生成探测。

当前原生前端仅在 ChatGPT 登录下显示 Fast；纯 API 身份的界面限制保持原样。发布前对四个 GPT 网关模型做了普通／Fast 的实际输出速度对照，均观察到提速，但不承诺固定倍率。响应中的 `service_tier` 不能单独证明是否提速。

图片模型名称转发已核对；上游实际执行型号仍需其接口保证。部分订阅转发接口接受未知型号，原始响应和 C2PA 凭证又未记录具体版本，因此不能把成功生图或网关回显等同于已确认 Flare／Sunburst。原生工具没有新增模型、格式或动画控制参数。

## 安装与更新

完全退出客户端后安装到原目录，保留已有 `data/`、登录和聊天。重新打开控制台后，在“模型与上下文”刷新模型目录；保存设置后重开客户端应用。Windows / macOS 提供三个聊天入口和控制台，Linux 提供纯 API 入口和控制台。

macOS 仍使用 ad-hoc 签名，未经过 Apple 公证，首次打开沿用系统正常的手动允许流程。旧版本保留在各自目录，不提供独立 `.sha256` 文件。完整说明见 [README](../../README.md)。
