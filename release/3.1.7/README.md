## 图片模型与控制台

- 图片模型统一显示在“模型与上下文”，容量和单模型上限留空。“当前配置”可勾选一个“默认生图”，取消后恢复自动选择。
- 可以配置多个图片模型；默认生图独立于聊天模型和 API 来源优先级。补充图片模型 ID、编辑模型及 JSON / Multipart 格式集中到同页“图片接口设置”。
- 修复纯 API 入口的原生图片工具注册。带原生图片回合标识的自动请求使用控制台默认；直接调用 Images API 时，明确指定的模型优先。
- 混合入口已选默认 API 生图模型时直接使用该模型；未设置时保留官方优先、明确不可用后回退 API 的行为。官方入口仍只使用官方图片服务。
- 来源名称旁可直接重命名；已保存的 API Key 显示为密码圆点，点击眼睛可显示或隐藏实际 Key。查看 Key 需校验连接令牌、来源和配置修订号，普通状态接口不返回明文。
- “预计可用”改为“当前配置”，保留原生有效上下文比例；模型目录仍只在启动或手动刷新时请求，不增加轮询。

## 生图使用方法

在控制台添加并启用提供兼容 Images 接口的 API 来源，保存并刷新目录；到“模型与上下文”选择“默认生图”，保存后完全退出客户端，再从对应入口重开。

**当前原生 `image_gen` 没有模型参数，在聊天中说“用某某模型画图”不能可靠切换。** 需要换模型时在控制台修改默认并重开。Images API 的 `model` 字段可以明确指定模型，这是直接接口调用的能力。仅编辑模型不能设为默认生图，缺少模型、接口或对应权限时明确报错。

## 安装与兼容边界

更新前完全退出客户端，使用原安装目录并保留 `data/`。Windows / macOS 保留三个聊天入口和控制台；Linux 仅提供 API 入口与控制台。安装仍可跳过 API 配置，稍后再填。

本次不修改官方客户端，不新增提示词或聊天，不改变登录和历史位置。跨官方 / API 入口续聊、官方加密上下文、部分工具的官方身份要求以及混合模式额度耗尽后的即时切换仍有边界，详见项目 [README](../../README.md)。

包内包含运行时和锁定依赖，不含个人配置、Key、登录、聊天或日志，不提供独立下载校验文件。macOS 仍为 ad-hoc 签名，未经过 Apple 公证；系统权限与真实设备功能以实际授权和客户端支持为准。
