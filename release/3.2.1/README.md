本版修复纯 API 入口重复初始化、项目分类丢失、登录存储和退出清理的问题，同时保留三个入口对不同 provider 历史对话的自动兼容。

- 官方入口统一命名为 `chatgpt-official`，另外两个入口为 `chatgpt-api` 和 `chatgpt-apionly`。
- 补齐真正的发送判断。混合入口按当前模型区分额度归属，自定义 API 模型使用自身服务额度，官方模型遵循订阅额度。兼容处理覆盖两项订阅额度状态，其他原生提交条件沿用客户端逻辑。

- 纯 API 入口使用原生自定义 provider 的 API 认证，登录存储沿用用户原设置。账户内项目、分类、引导状态和工作区偏好在运行期间复用，退出后归回原作用域。
- 修正空账户作用域触发原生清空的问题。旧恢复记录可恢复保存的原始设置。分类字段已缺失时，仅从原生快照恢复仍有项目索引对应的精确记录。
- 三个入口运行期间临时统一旧对话的通道标记，覆盖会话头、持久化设置和 SQLite 索引，退出后恢复原值。对话沿用原 ID、消息、工具历史和项目归属。
- Windows 的转发与界面兼容共用一个进程，由客户端主进程退出事件触发清理。覆盖正常退出、闪退、强制结束及适配进程崩溃，清理只针对本次启动记录的进程。
- macOS、Linux 的恢复守护通过进程间连接等待启动进程退出。正常运行期间采用事件等待，启动进程异常退出后才检查本次客户端的退出情况。
- 突然关机后的恢复在下次系统登录或启动入口时自动完成，完成后清除临时登录触发项。
- GPT API 模型保留原生 Fast 菜单和 priority 请求。官方兼容入口使用官方模型与远程压缩，API 入口使用原生文本压缩。混合入口可在同一原对话中切换官方和自定义模型。

Windows 已通过正式启动脚本、转发器和隔离原生桌面进程的完整启动与强退恢复测试，验证保留 11 个项目及 83 条分类映射。原生核心另验证不同 provider 的原对话续聊、并行请求、官方与 API 模型切换、Fast 参数和两种压缩。协议回归覆盖工具、媒体、暂停续聊及结构化输出。Linux 安装和 macOS 启动逻辑采用隔离环境验证，macOS 的系统权限、真实账户登录及完整桌面界面仍需实机验证。

官方加密上下文由支持对应协议的模型处理。直接从系统打开原版客户端，仍遵循原生 provider 规则。模型能力、工具登录要求及其他兼容边界见项目 README。

更新前完全退出客户端，安装到原目录以保留 API 设置。macOS 对外仅提供 DMG，保留系统正常手动允许流程。完整用法、架构和其他边界见项目 [README](../../README.md)。
