本版解决新版客户端按 provider 限制旧对话续聊的问题。通过 chatgpt-api、chatgpt-apionly 或官方兼容入口，可以自动打开并续聊本机不同来源创建的原对话，无需选择“历史兼容”或为不同旧记录反复重启。

- 移除控制台的历史通道选择及旧配置开关。运行期间临时统一通道元数据，退出后恢复原值；原对话 ID、消息、工具历史和项目归属保留。
- 临时处理涵盖会话头、持久化通道设置和 SQLite 索引，避免续聊时恢复到旧标签。恢复日志仅保存在适配层目录，完成恢复后清除；不向客户端目录写入备份或兼容配置文件。
- 纯 API 入口采用原生临时认证配置，忽略保存的订阅身份与额度，沿用已有项目、偏好、工作区和引导状态。登录凭证保留在原位置，退出后恢复原设置。
- 支持的 GPT API 模型可免订阅登录使用原生 Fast 菜单与 priority 请求。混合入口中，官方额度耗尽后可切换至自定义模型继续发送。界面兼容仅在内存中生效。
- 官方兼容入口保持官方模型、认证和远程压缩；两个 API 入口使用原生文本压缩。混合入口可在同一原对话中切换官方和自定义模型。
- 三平台退出时恢复临时设置；原来没有配置文件时，不留下空文件或新增 provider 定义。独立后台守护处理异常退出，系统登录自动处理突然关机后的遗留状态，完成后删除临时登录触发项，无需额外操作。安装和配置 API 时仅更新适配层目录。

Windows 最新原生核心 0.167.0-alpha.3.2 配合隔离接口验证通过：不同旧 provider 的原对话、并行续聊、官方/API 模型切换、Fast 参数、原生压缩、终端和文件工具、MCP、暂停续聊、媒体消息及结构化输出。Linux 安装包和 macOS 启动逻辑另做隔离测试；真实模型能力、账号权限和实际网络仍以各服务为准。

本版不修改官方安装文件、不添加提示词、不生成替代聊天记录，也不新增依赖。官方加密上下文仍无法由其他厂商模型解密；直接绕过启动器打开原版客户端，仍遵循原生 provider 限制。模型不具备的能力和原生工具的登录要求不由本项目补足。

更新前完全退出客户端，安装到原目录以保留 API 设置。macOS 对外仅提供 DMG，保留系统正常手动允许流程。完整用法、架构和其他边界见项目 [README](../../README.md)。
